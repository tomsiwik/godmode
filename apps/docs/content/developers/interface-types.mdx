title: Interface types

Every extension declares one or more interfaces. The interface dictates how godmode dispatches calls and what `--help` looks like at the inner levels.

## At a glance

| Interface | Source of truth | Best for | Live example |
|---|---|---|---|
| **`api`** | OpenAPI 3.x spec | REST APIs (most third-party services) | [stripe](/extensions/stripe), [openai](/extensions/openai), [slack](/extensions/slack), [petstore](/extensions/petstore) |
| **`graphql`** | SDL file or introspectable endpoint | GraphQL APIs | [github](/extensions/github) |
| **`mcp`** | MCP server (stdio or HTTP) | Existing MCP servers, custom tooling | [context7](/extensions/context7), [claude-code-channels](/extensions/claude-code-channels) |
| package-defined | Exported interface class | Desktop apps, device control, or another invocation model | Your npm extension |

## Decision tree

```
Does the upstream publish an OpenAPI 3.x spec?
├── Yes → api
└── No
    ├── Is it GraphQL?
    │   ├── Yes → graphql
    │   └── No
    └── Is there already an MCP server for it?
        ├── Yes → mcp (point at the existing server)
        └── No → export a package-defined interface for the native interaction model
```

## `api` (REST)

Routes derived from an OpenAPI 3.x document. godmode parses paths, methods, parameters, and request/response shapes — `--help` shows them all.

```yaml
interfaces:
  api:
    spec: https://example.com/openapi.yaml
    url:  https://api.example.com
```

**Strengths:** zero runtime code, automatic parameter validation, `--help` doubles as API documentation.

**Limits:** only as good as the upstream spec. Missing `operationId`s, vague descriptions, or missing examples mean less helpful `--help` output. (godmode synthesizes operationIds from method+path when missing.)

## `graphql`

Either a local SDL file or an introspectable endpoint.

```yaml
# SDL-based
interfaces:
  graphql:
    spec: ./schema.graphql

# Introspection-based
interfaces:
  graphql:
    url: https://api.github.com/graphql
```

**Strengths:** schema awareness; users can ask `--help` for a type or field. Single endpoint, no per-route parsing.

**Limits:** introspection requires network access at install time and may be disabled for private GraphQL APIs (you'll need to ship the SDL with the package).

## `mcp` (Model Context Protocol)

For wrapping existing MCP servers, or for cases where the upstream tool surface is best modeled as MCP tools (not REST routes).

### Spec-based (HTTP MCP server)

```yaml
interfaces:
  mcp:
    url: https://example.com/mcp
```

godmode connects over HTTP, lists tools, exposes them as `godmode <ext> mcp <tool>` invocations.

### Package-based (stdio MCP server)

For when the MCP server is itself a binary or script you ship in the same npm package:

```yaml
interfaces:
  mcp:
    command: node
    args: ["dist/server.js"]
```

The package's `package.json` ships the binary; godmode spawns it on demand. See [`extensions/claude-code-channels`](/extensions/claude-code-channels) for a complete example.

## Package-defined interfaces

Use an interface class when `api`, `graphql`, and `mcp` do not describe how callers
interact with the extension. For example, an application interface can expose
`godmode finder app open document.pdf` without teaching core about an `app` keyword.

Export the class from `package.json`:

```json
{
  "exports": {
    "./manifest": "./manifest.yaml",
    "./interface": "./dist/app.js"
  }
}
```

The default export is one interface class, or an array when the package defines more
than one. Each class owns its key, help usage, installation compiler, and runtime
behavior:

```ts
import { Interface, type InterfaceData, type ManifestSource } from 'godmode/interface';

export default class AppInterface extends Interface {
  static readonly key = 'app';
  static readonly usage = ' <action> <application>';

  static async compile(_name: string, source: ManifestSource): Promise<InterfaceData> {
    const app = source.interfaces.app as { application: string };
    return {
      type: this.key,
      application: app.application,
      specVersion: 'app-v1',
      versions: [],
      resourceDescriptions: {},
      routes: [],
    };
  }

  async execute(): Promise<void> {
    const [action, application] = this.ctx.parsed.segments;
    // Perform the declared app action and write its result to stdout.
  }
}
```

The manifest declares the same lowercase key:

```yaml
interfaces:
  app:
    application: Finder
```

The CLI loads the class before validating and compiling the manifest, records the
compiled data, and loads the same class for later invocations. A second package cannot
replace an interface key already registered in the process.

An interface module is executable package code. Installing or invoking it gives that
code the same process authority as godmode; use only packages you trust.

## Multiple interfaces

You can declare more than one — useful when an API has both an OpenAPI spec and a richer MCP wrapper:

```yaml
interfaces:
  api:    { spec: ... }
  mcp:    { command: node, args: [...] }
```

Then both `godmode myext api ...` and `godmode myext mcp ...` work. See [Multi-interface extensions](/developers/multi-interface).

## Derivative MCP serving

Even an `api`-only or `graphql`-only extension can be served as an MCP server *without* declaring `mcp:` — `godmode <ext> mcp` synthesizes one. See [MCP serving](/developers/mcp-serving) for how the synthesis works.
